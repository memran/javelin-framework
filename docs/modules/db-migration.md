# Database Migration Module

Artifact: `io.javelin:javelin-db-migration`

`javelin-db-migration` runs YAML schema migrations against any core `Database`. It owns the migration history table, batch tracking, rollback, and backend-specific history DDL. `javelin-db-jdbc` registers it automatically; you can also use it with another `Database` implementation.

## MigrationRunner

```java
MigrationRunner runner = new MigrationRunner(database, Path.of("database/migrations"));
List<String> applied = runner.migrate();
List<String> rolledBack = runner.rollback();
List<Path> files = runner.migrationFiles();
```

- `migrate()` -- ensures the `javelin_migrations` history table exists, then runs each pending migration and records its filename, batch number and timestamp in one transaction.
- `rollback()` -- rolls back every migration in the latest batch, in reverse order, within one transaction per migration.
- `migrationFiles()` -- lists `.yml`/`.yaml` files sorted by filename, so timestamped names control order.

Each migration file has `name`, `up` and `down` keys:

```yaml
name: create_users
up:
  - sql: |
      create table users (
        id bigint generated by default as identity primary key,
        email varchar(255) not null
      )
down:
  - sql: drop table users
```

## Dialects

The history table DDL differs across backends. `MigrationDialect` supplies it, and `MigrationDialects` provides three built-ins:

| Factory | Backend | Key column |
|---|---|---|
| `MigrationDialects.POSTGRESQL` | PostgreSQL | `bigint generated by default as identity` |
| `MigrationDialects.MYSQL` | MySQL / MariaDB | `bigint auto_increment`, `varchar(191)` |
| `MigrationDialects.SQLITE` | SQLite | `integer primary key autoincrement` |

```java
MigrationRunner runner = new MigrationRunner(database, dir, MigrationDialects.SQLITE);
```

`MigrationDialects.from(String hint)` selects a dialect from a driver class name or JDBC URL. `JdbcDatabaseServiceProvider` derives the hint from the default connection. The two-argument constructor keeps PostgreSQL as the default for backward compatibility.

## Backward compatibility

`io.javelin.db.jdbc.MigrationRunner` remains as a deprecated subclass of this class, so existing imports keep compiling. New code should import `io.javelin.db.migration.MigrationRunner`.
